Node.js est un environnement d’exécution JavaScript côté serveur. Il repose sur le moteur V8 de Google Chrome. Il permet d’exécuter du JavaScript hors du navigateur. Il a été créé par Ryan Dahl en 2009. Il est open source et soutenu par la fondation OpenJS. Son modèle central est l’entrée/sortie non bloquante. Il utilise une boucle d’événements pour gérer les opérations asynchrones. Il est souvent décrit comme mono-thread pour le code JavaScript. Les opérations lourdes sont déléguées à libuv et au système. libuv fournit la boucle d’événements et le pool de threads. Le pool de threads gère par défaut certaines tâches système. Node.js excelle dans les applications réseau et temps réel. Il est adapté aux API REST et aux microservices. Il est moins adapté aux calculs CPU intensifs purs. npm est le gestionnaire de paquets associé à Node.js. npm permet d’installer, publier et gérer des dépendances. package.json décrit un projet et ses scripts. package-lock.json verrouille les versions des dépendances. node_modules contient les dépendances installées localement. Les modules intégrés incluent fs, http, path et os. fs permet de lire et écrire des fichiers. http permet de créer des serveurs HTTP sans framework. path manipule les chemins de fichiers de façon portable. os fournit des informations sur le système d’exploitation. CommonJS utilise require et module.exports. Les modules ES utilisent import et export. Node.js prend en charge les deux systèmes selon la configuration. Les callbacks sont une forme historique d’asynchronisme. Les promesses améliorent la gestion des opérations asynchrones. async/await rend le code asynchrone plus lisible. La boucle d’événements traite les callbacks prêts. Les opérations d’E/S ne bloquent pas la boucle. Une opération bloquante peut ralentir tout le processus. Les streams permettent de traiter des données par morceaux. Les buffers représentent des données binaires brutes. Les streams sont utiles pour les fichiers volumineux et le réseau. pipe relie facilement des flux entre eux. EventEmitter permet d’émettre et d’écouter des événements. De nombreux objets Node.js héritent d’EventEmitter. process donne accès aux variables et événements du processus. process.env contient les variables d’environnement. process.argv contient les arguments de ligne de commande. La REPL permet de tester du JavaScript interactivement. node fichier.js exécute un fichier JavaScript. nodemon redémarre automatiquement l’application en développement. Express est un framework web minimaliste très populaire. Fastify est une alternative orientée performance. NestJS propose une architecture plus structurée. Les middlewares traitent les requêtes avant les routes. Les routes associent une URL et une méthode à un gestionnaire. Les erreurs asynchrones doivent être gérées correctement. try/catch fonctionne avec async/await. Les rejets de promesses non gérés peuvent arrêter le processus. Un serveur HTTP écoute généralement sur un port. Les WebSockets permettent une communication bidirectionnelle. Socket.IO simplifie les applications temps réel. Node.js est fréquent pour les chats et les tableaux de bord. Il peut servir des fichiers statiques avec fs ou un framework. Il peut se connecter à des bases SQL et NoSQL. Les pilotes de bases de données sont souvent asynchrones. Les ORM comme Sequelize ou Prisma facilitent l’accès aux données. La gestion des dépendances doit être prudente. Les audits npm détectent des vulnérabilités connues. Il faut valider et assainir les entrées utilisateur. HTTPS est recommandé en production. Les secrets ne doivent pas être codés en dur. dotenv charge des variables depuis un fichier .env. Les logs aident à diagnostiquer les problèmes. Les outils de debug incluent l’inspecteur intégré. node --inspect active le débogage. Les tests peuvent utiliser Jest, Mocha ou node:test. Les tests unitaires vérifient des fonctions isolées. Les tests d’intégration vérifient les interactions. Les tests de charge mesurent la performance. Le clustering exploite plusieurs cœurs CPU. worker_threads permet du parallélisme pour les tâches CPU. child_process lance des processus externes. La gestion mémoire est assurée par le ramasse-miettes de V8. Les fuites mémoire peuvent venir de références conservées. Les profils mémoire aident à détecter ces fuites. La mise en cache améliore les performances. Redis est souvent utilisé comme cache externe. Les files d’attente gèrent les tâches longues en arrière-plan. Des outils comme BullMQ s’appuient sur Redis. La conteneurisation avec Docker est courante. Les plateformes cloud prennent souvent en charge Node.js. Les versions LTS sont recommandées en production. Les versions non LTS servent à tester les nouveautés. nvm permet de changer facilement de version de Node. Le code doit rester non bloquant dans les routes. Les calculs lourds doivent être déplacés hors de la boucle. Les promesses parallèles utilisent Promise.all. Promise.allSettled gère les succès et les échecs. La pagination évite de charger trop de données. La compression réduit la taille des réponses. Les en-têtes de sécurité protègent l’application. La surveillance en production est essentielle. Node.js est rapide pour les E/S concurrentes. Son écosystème npm est immense et varié. Node.js est un choix puissant pour le JavaScript full-stack.
